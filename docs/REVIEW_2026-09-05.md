# Uptime402 검토 — 2026-09-05

## 범위와 결론

결제 executor, vendor, control plane의 상태 전이와 증거 생성, 공개 replay UI, 테스트와 빌드를 검토했다. 현재 공개 배포는 읽기 전용이므로 아래 실행 경로 문제는 새 결제 기능을 다시 활성화할 때 특히 중요하다. 기존 Devnet 결제의 진위를 부정하는 결과는 아니다. 새 결제, 배포, 보존된 evidence 변경은 수행하지 않았다.

## 확인한 문제

### 1. [P1] 결제 후 실패를 재개 가능한 상태로 반환하지 않는다

- 위치: [live-flow.ts:1328](/Users/kwakhyun/Documents/gcp-solana-ai-agentic-hacks/apps/control-plane/src/server/live-flow.ts:1328), [operator-boundary.ts:730](/Users/kwakhyun/Documents/gcp-solana-ai-agentic-hacks/apps/control-plane/src/server/operator-boundary.ts:730).

Private checkpoint를 쓰기 전 프로세스 종료나 checkpoint 저장소 자체의 실패는 자동 재개 보장이 아니다. 이 경우 reservation을 임의 해제하거나 새 결제를 만들지 말고 기존 vendor reconciliation과 private 감사 기록으로 확인해야 한다. 재개 명령의 설정과 한계는 `deploy/README.md`에 기록했다.

2026-09-05 후속 요청에 따라 주요 화면, 상세 증거, 실행 예시, 운영자 안내와 README의 문구를 정리했다. ‘정책 결제’는 ‘정책 확인과 결제’로, ‘판단 기록부터 … 뒤’는 ‘판단 기록 후 … 만에’로 바꿨다. 설명에 섞여 있던 불필요한 영어는 한국어로 풀고 프로토콜명, API 필드명, 해시와 금액은 유지했다. Gemini의 견적 선택과 결제 실행기의 역할도 문장에서 구분했다.

공개 화면 배포를 준비 중이다. 배포 후 revision과 검증 결과는 BUILD_STATUS 및 portfolio deployment manifest에 기록한다.
